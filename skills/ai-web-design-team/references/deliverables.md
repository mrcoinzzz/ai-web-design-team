# Consolidated output

Scale the output to the task. Prefer one recommendation over an unranked collection of reviewer reports.

## Review

Start with the main design problem or opportunity, then state inspected pages, states, viewports, and evidence limits. Highlight useful existing choices to retain.

Return the strongest findings, normally no more than five to eight. Each needs:

- **Location and evidence:** the section/control plus screenshot, source location, or observed interaction.
- **Impact:** the user task affected; distinguish observation, design judgment, and conversion hypothesis.
- **Change:** exact copy, component/layout behavior, or a concrete style adjustment.
- **Priority and confidence:** high for blocked tasks or serious comprehension/access issues; medium for substantial hierarchy/friction problems; low for polish. Explain uncertainty rather than assigning spurious numerical scores.
- **Verification:** what observation or test would establish the change works.

Merge duplicate findings. Resolve meaningful disagreements explicitly, including which constraint drove the decision. End with an ordered implementation sequence when useful, not an automatic request for permission to continue.

## Redesign or build

Provide a compact design rationale, preview/artifact links, implemented scope, and verification summary. A useful summary distinguishes:

| Check | Evidence | Result |
| --- | --- | --- |
| Appearance | Actual route, viewport, capture | Passed, failed, or unverified |
| Required behavior | Interaction and observed destination/state | Passed, failed, or unverified |
| Project checks | Actual command and outcome | Passed, failed, or not run with reason |

Use real results, not a prefilled success table. Mention any deferred requirement or missing business fact that affects readiness. Keep internal specialist notes out of the final unless the user requests them.

For substantive work, summarize the visitor problem and success criterion, the shared style/component sources changed, and the primary journey checks including relevant failure/recovery paths. Fold this into the existing handoff rather than producing three extra reports. Keep unmeasured outcomes and proposed usability studies visibly separate from completed verification.
