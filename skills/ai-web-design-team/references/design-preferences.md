# River's lightweight preference discovery

Help users describe what they like in ordinary language. First read the current brand, supplied examples, and previous decisions. Don't ask them to repeat preferences already provided.

If a substantial design choice is still unclear, one optional question can help: “What should we keep, what feels wrong, and is there a site whose look you like?” They may answer any part. Lack of design vocabulary is not a blocker. Infer reversible choices from the offering and audience and label the direction as a recommendation.

Translate preferences into decisions. “Less busy” may mean fewer competing accents, shorter line lengths, and clearer grouping. “More premium” needs a concrete interpretation such as editorial typography and restrained emphasis; it is not a reason to hide required actions, invent proof, or sacrifice readability.

## When two directions help

Use two small alternatives when the user asks to compare, or when a broad redesign/new site has genuinely different plausible compositions and no established direction. Skip this for a narrow change, a clear brand brief, or a previous choice. Respect stricter project/host instructions about design previews.

Compare the same real content and required action. Change composition, type hierarchy, density, or image treatment—not merely the accent color. A compact description is enough for early discussion; use small rendered concepts when the request calls for visual comparison and tools permit it. Don't build two whole sites.

| Direction | Concrete choices | Tradeoff |
| --- | --- | --- |
| Editorial | Strong headline, generous spacing, one clear reading sequence | Quieter presentation; less detail above the fold |
| Product-led | Compact introduction beside a useful product view; denser feature grouping | Faster capability scanning; more visual information to manage |

These illustrate comparison dimensions, not two mandatory house styles. Recommend the option that best serves the brief and explain why. For requested implementation, proceed with the justified choice unless the user requested a selection checkpoint or an unresolved business fact blocks it. If they ask to choose first, wait for that choice before dependent implementation.

## Keep the choice in the existing brief

Record: chosen direction and reason; what to keep; what to avoid; typography/spacing/imagery/tone decisions; scope; remaining uncertainty. Reuse this note in follow-ups. If the user changes their mind, update the note and affected work rather than mixing incompatible directions. Save to a project file only when useful and within scope; no permanent-memory setup is required.

Example: “Chosen: editorial, to explain the offer before showing detail. Keep the blue identity and login access. Avoid gradients and dense card grids. Use a large concise heading, generous sections, and compact product evidence. Mobile remains a single reading sequence. Imagery is not needed for this product fixture.”
